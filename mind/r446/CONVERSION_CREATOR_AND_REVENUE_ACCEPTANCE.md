## Minimal privacy-preserving measurement contract (spec only; do not install script)
Use existing approved first-party analytics/configuration; Claude to check if native instrumentation already emits the required events. **Never duplicate tracking libraries or add pixel vendors.** Capture only allowable coarse channel, campaign, immutable non-sensitive `asset_id`, destination path, variant, event type, coarse date, consent status and an ephemeral/non-reidentifying session count where supported. Drop query parameters not on an explicit allowlist, strip email/token/PII, omit precise IP, user-agent fingerprint, session replay, and third-party trackers. Store aggregated 7/30 day cohorts, suppress tiny cells and report bot/QA traffic exclusions as estimated, not incontrovertible human classification.

Required event states with mutually distinct names:
`qualified_campaign_landing` → `article_to_focus_click` → optional **provider-confirmed** `focus_signup_confirmed` → `buyer_guide_view` → **authorized** `affiliate_click` → independently verified `merchant_order_paid` or `affiliate_commission_settled` → `refund_or_fee_adjustment`.

**A click is not a checkout start, signup is not a paid order, and neither is a commission.** Never infer attributed purchases from query tags alone. Cross-domain attribution requires legal/partner rights and merchant reporting. If commission settlement cannot be tied back to a qualified campaign, report aggregate paid commission separately as unattributed and leave campaign ROI unknown.

`Net revenue per 1,000 qualified-human sessions = 1000 × (confirmed settled owned-product receipts + confirmed settled affiliate commissions − attributable refunds − payment/fulfillment/platform fees) / eligible qualified-human sessions`. Record unknown denominators as **not computable**, not zero; expose tiny-sample uncertainty and refund lag. Maintain distinct 7/30-day acquisition cohort dates and settlement dates.
