## A/B hypothesis and prespecified measurement boundaries
**A (guide only)** and **B (same guide + film)** differ in presentation only. This is a test hypothesis: visual context might increase *qualified interest*, but might also distract or slow a page. No actual traffic has been split and no conversion improvement is known. Avoid winner language without a genuinely randomized experiment and sufficient observations.

Before any authorized study, establish: one first-party campaign assignment method, stable variant allocation, consent/legal basis if applicable, normal accessibility and no-JS fallback, documented consent and partner terms, an on-site privacy notice, and the ability to stop measurement without breaking pages. Avoid ad IDs, IP, full URLs, email, fingerprinting, query strings, browser storage, third-party pixels and private merchant referral parameters. Favor aggregate server-side counters or existing approved Jetpack aggregate reporting instead of client tagging where feasible. Define separate numerator/denominator pairs: article views → guide entry; guide entry → voluntary Focus resource interest; guide entry → outbound offer (only once authorized). Do **not** present outbound clicks as confirmed purchases, and don't fetch buyer-level conversions from the merchant. Use group suppression for count < 20. The committed module is illustrative and **disabled**.

**Performance budget (release proposal, not a measured production fact):** zero JS, CSS limited to page scope, no third-party embeds, optional first-party poster (target <100 KB optimized), compressed H.264/WebM if published with captions and `preload=none`, no autoplay or forced playback. Native controls, captions, visible transcript and reduced-motion/no-JS versions. Measure LCP/CLS/INP and actual phone viewport load on staging **before** any approval; don't claim a lab test that hasn't occurred.
