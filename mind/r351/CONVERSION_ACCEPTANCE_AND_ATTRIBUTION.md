## 4. Controlled A/B: core buyer text identical
**Hypothesis, not observed fact:** an original optional 42-second explanatory film treatment could improve visitor understanding and eventual merchant-confirmed paid conversion versus the same accurate, useful text-only guide. It could also distract, slow the page or reduce conversions.

- A: `ZEN12_A_TEXT_GUIDE.html` with research-led intro, true package contents, free exercise, objections and near-CTA disclosure; disabled button.
- B: identical six core buyer-copy sections plus standalone original 42-second poster, transcript and six caption cues. Poster/storyboard **does not count as a playable video**; encode media and verify captions before any authorized staging test.
- Delivery: both `noindex,nofollow` review pages. No JS, no autoplay, no extra form, no active earning URL, no hidden checkout. Compatible with keyboard and small screens in source; real-browser acceptance still required.
- Proposed stage assignment after permission: use existing first-party campaign routing with opaque A/B variant key, 1:1 fixed randomization; no cookies or personal profiles unless the existing privacy/consent decision allows them. Do not silently add tracking scripts. Use the same visitor intent, merchant and CTA surface for both variants. Avoid changing disclosure, checkout destination or seller offer between arms.
- **Primary endpoint:** independently confirmed paid purchase or commission actually credited and reconciled net of refunds/fees per 1,000 qualified human sessions, measured in 7- and 30-day cohorts. Secondary: confirmed checkout starts, relevant CTA clicks, verified opt-in, bounce/performance and source completion. Outbound clicks are *not* sales.
- Stop or redesign for mobile friction, clear disclosure failure, mismatch with Grok hook, unpermitted channel, misleading promise or unmeasurable merchant payout. Do not declare a winner with sparse data or a simple bounce-rate change.

Unique external creative uses `asset_id` exactly as supplied by Grok; proposed example only: `utm_source=tiktok&utm_medium=organic_social&utm_campaign=mind_suggestion_pilot_2026_11&utm_content={verified_asset_id}`. Never invent an active `asset_id`. Preserve platform link constraints; record permitted bio-link hops, do not assume direct clickthrough.

**Event schema, only if existing approved analytics supports it:** `campaign_landing` with `utm_source`, `utm_campaign`, `utm_content`, `landing_route`, `experiment_variant` (coarse, non-PII); `article_to_fieldbook_click`; `confirmed_signup` only from Jetpack/provider-confirmed state; `affiliate_outbound` only after approved real URL; `verified_checkout_start` only with reliable provider confirmation; `merchant_confirmed_paid_order` or `merchant_confirmed_paid_commission` from authenticated transaction reports; `refund` and `merchant_fee` reconciled to same non-identifying period/product key.

Prohibit IP logging, names, emails, raw device fingerprints, intrusive user profiles and URL fragments containing personal data. Do not stitch anonymous sessions into individuals. Apply documented qualification/bot filtering and consent controls chosen by Claude/privacy review; retain aggregate per-cohort counts and provenances. If denominators cannot be independently established, report **NOT COMPUTABLE**.

**Formulas:** `net_realized = merchant_confirmed_settled_gross - attributed_refunds - merchant_fees - other verified processing fees`; `NRP1K = 1000 * net_realized / qualified_human_sessions` only if all terms are verified and denominator > 0. `paid_conversion_rate = confirmed_paid_orders / qualified_human_sessions`. `lead_to_customer = identifiable-with-consent verified purchasers who previously opted in / provider-confirmed cohort leads` only if privacy/legal identity join is approved; otherwise `NOT ATTRIBUTABLE`.

Never substitute an affiliate click, a preliminary email entry, a cart click, a hypothetical rate or the vendor's public program average for an actual paid transaction.
