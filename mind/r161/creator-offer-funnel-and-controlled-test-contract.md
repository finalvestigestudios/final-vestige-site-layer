## Video experiment: useful design, no false conversion claim

- **Control A:** identical full text buyer guide and free Focus CTA; no video preview.
- **Treatment B:** same order, wording, controls and commercial eligibility, plus **optional** original 40-second **click-to-play**, muted by default only if explicitly chosen, no autoplay and no third-party iframe. Same-site compressed MP4 + poster + WCAG-ready VTT and always-available HTML transcript. Target under 500KB additional transfer for short video if feasible *without harming quality*; enforce real measured performance budget before release. Never load video bytes before a person requests playback (video preload=none).
- **Current implementation:** only a poster concept and complete 40s transcript/storyboard in semantic HTML. No MP4, VTT, actual poster image, video player, captions QA or variant assignment exists. The unproduced-video box is explicitly labeled rather than passing off broken media as tested. Grok owns actual video creative only if coordinated, not Mind.
- **Randomization:** after release governance/partner approval, first-party deterministic assignment per eligible qualified session (one person/session in one arm; consent-respecting, no persistent cross-site identifier). For the *first* round with no commercial authorization, test only free-resource **intent** on staging with consenting testers; do not call that sales. Production variant split needs independent tracking QA and approved source-safe design.
- **Primary predeclared endpoint (only after merchant verification):** independently settled **net revenue per 1,000 qualified human sessions** by variant, adjusting for seller-reported commissions, fees, refunds. Secondary: independently confirmed paid orders (unique order IDs), purchase rate, verified lead-to-purchase rate where consented. Tertiary diagnostic: free CTA, product-guide engagement, outbound event and scroll. A click is NOT a purchase.
- **Power/ethics:** no early winner declaration from dozens of visitors. Pre-register sample size and minimum detectable effect using realistic baseline paid conversion data (currently missing). Include absolute counts, conversion denominators, 7/30-day cohorts, uncertainty intervals and sample-size warning. Compare equal time windows and traffic-source mix, dedupe repeated arrivals. Keep losing variant accessible and free alternatives intact.
- **Negative outcomes to track:** higher bounce, stale pricing, failed captions, confusing disabled controls, extra bytes delaying LCP, lower verified purchase intent, or user reports of inaccurate claims. If video doesn't help, retain text. No paid testing vendor.

## First-party campaign attribution contract (proposal, not installed)

**Campaign landing taxonomy:** unique Grok native asset_id (safe non-PII opaque string supplied by creator) + utm_source (exact platform) + utm_medium=organic_social + utm_campaign=fv_mind_2026q4_<topic> + utm_content=<verified_asset_id>. Don't invent URLs/IDs or distribute tags until creator and engineering approval. Landing record should contain approved content slug, source and consent state, not IP, emails, names or raw user-agent fingerprint.

**Event state machine:**
1. Qualified-human landing/session — human/bot classification rule set by site analytics owner, not inferred from WordPress pageviews.
2. article_to_focus_click — actual browser action (not page load).
3. confirmed_signup — Jetpack authoritative confirmation *only* if observable; clicking free link is not a lead.
4. affiliate_outbound — only after partner authorization, disclosure and actual tracking permit; never a commission.
5. verified_checkout_start — only when partner provides an auditable authenticated signal; do not assume click implies checkout.
6. merchant_confirmed_paid_order / independently reported paid_affiliate_conversion — paid unique order/commission event from merchant reports; do not expose buyer PII.
7. settled_net_revenue — gross paid receipts/earned commission minus fees, refunds, chargebacks and adjustments, reconciled to actual settlements.

Avoid duplicate analytics scripts; reuse first-party event contracts specified in [Issue #820](https://github.com/finalvestigestudios/final-vestige-site-layer/issues/820). Avoid email-body click IDs linked to identities or non-consensual fingerprinting. Use aggregate reporting with counts and provenance. For affiliates, no sales API is presumed; reconcile official reports manually if needed. Separate unverified clicks and unsettled commissions.

**KPI formula:** (settled attributable net revenue / qualified human sessions) × 1,000, shown **NOT COMPUTABLE** when either verified numerator or denominator missing. A zero should only be reported when both inputs were measured and the numerator was zero. Report refund window, currency, 7d and 30d cohort assignment and very small-n warnings.
