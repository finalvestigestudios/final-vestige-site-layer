# R144 — offline replay CLI argument privacy (DRAFT / HARD RELEASE HOLD)

## The bug and the boundary

R143's local verifier protects its runtime exceptions with a generic HOLD message, but its `argparse.parse_args()` previously executed **outside** that privacy boundary. The standard `argparse` error path prints rejected option values and flags directly to stderr before exiting with status 2. A hurried operator might paste a private source pathname, account number, or amount as `--window-days`, `--kind`, an unexpected option, or a stray positional argument; the resulting console transcript or captured CI/job log would echo it.

R144 uses a small `_PrivateArgumentParser` subclass whose `error()` raises a fixed internal ValueError, and parses inside the existing replay privacy exception handler. Invalid arguments now return **exit code 1** and exactly the established generic `REPLAY HOLD` line, without `usage:`, rejected values, customer filenames, or Python tracebacks. The intentionally static `--help` response retains normal argparse exit-code-0 behavior. This change does **not** affect `verify_report()`, CSV source handling, serialized reports, file hashes, the engine's exact Decimal rules, or legacy valid CLI arguments.

### Threat scope and operator guidance

- An invalid unknown flag, product name, malformed integer, missing required flag, stray positional filename, option-shaped source, or inapplicable mapping must produce one generic HOLD message with no client-controlled content.
- The CLI still prints the selected **free** product kind, SHA-256 of the verified report, and source count **only after** a successful reproducibility check. It never prints customer paths on success.
- Do not paste client secrets into command arguments: an OS process list, shell history, upstream job runner, terminal settings, or caller itself can record argv **before our parser runs**. This fix limits diagnostics generated by the replay verifier, not those independent surfaces.
- `--help` prints static usage text. An unhandled operating-system/process failure cannot be treated as a successful audit.
- A matching replay proves byte reproducibility against selected originals under the current engine only, not source authenticity, accuracy, financial approval, compliance, or licensing. No private data leaves the machine, and neither premium application is unlocked.
