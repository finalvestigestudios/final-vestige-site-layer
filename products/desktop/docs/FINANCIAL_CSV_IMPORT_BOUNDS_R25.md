# R25 — bounded financial CSV imports and NUL/encoding integrity

**Status:** development-only, stacked draft branch; no approved Windows binaries or download URLs.

## Why this matters

The shared financial CSV importer was bounded to 200,000 logical records, but
had **no input file-size ceiling**. A very large local export (or sparse file)
could be read into memory during a normal workflow. Python's CSV reader can also
accept embedded NUL characters in headers or values, including columns that the
selected engine does not map, producing potentially untrustworthy evidence.

A malformed UTF-8 header/row could previously raise a raw decoder exception.
The user now gets a generic CSV parsing error, without printing the cell bytes.

## Changes

- All five financial apps sharing `fvs_suite.engine.table` now enforce
  **64 MiB per input CSV file**. This matches the existing premium review-report
  cap. The check uses the **opened file descriptor** before parsing and checks
  the descriptor again after parsing. It rejects both oversized regular files
  and sparse files immediately. This is a file-size and normal-use memory guard,
  **not** a guarantee against adversarial concurrent mutation mid-read.
- Reject embedded `U+0000` in **any CSV header or data field**, including
  fields not selected by the operator. The error identifies the physical record
  line for data, not the sensitive cell contents.
- Wrap malformed CSV and UTF-8 decoding exceptions as user-facing
  `ValueError` messages. No unvalidated output is generated by the five apps.
- Preserve UTF-8 BOM support, quoted multiline fields, real physical source-line
  references, normal non-ASCII text, Decimal-safe amounts, and human-review flags.
- Do **not** treat a matching financial total as authorization, grant eligibility,
  a purchasing approval, or an automated compliance conclusion.

Impacted free utilities: **LedgerDiff Lite**, **Invoice Twin Scout**,
**SpendMap Lite**. Impacted premium utilities: **GrantAudit Studio Pro**,
**ProcureGuard Studio Pro**. **Policy Delta Desk** handles policy text, not
financial CSV ingestion, and retains its existing separate 10 MiB policy limit.

## Operator impact

Exports above 64 MiB should be partitioned into separately reviewed batches
without changing source originals. Preserve all source-file provenance and
manually combine/report cross-batch findings. A CSV containing an embedded
NUL must be corrected at its source and re-exported; do not automatically
strip the character, since doing so might silently change an identifier.

These changes do not encrypt plaintext working reports, prevent external
tampering with local source files, or certify the accuracy of imported records.

## Regression checks

Run from the repository root with Python and pinned desktop dependencies:

```sh
PYTHONPATH=products/desktop python -m unittest discover -s products/desktop/tests -p 'test_csv_import_bounds_r25.py' -v
PYTHONPATH=products/desktop python -OO -m unittest discover -s products/desktop/tests -p 'test_csv_import_bounds_r25.py' -v
PYTHONPATH=products/desktop python -m unittest discover -s products/desktop/tests -v
```

The module contains **15 repository regression methods**: byte-size
boundary/sparse-file checks, malformed UTF-8, NUL in required and ignored
fields, normal BOM/multiline/Unicode compatibility, redacted errors,
and no partial audit report from all five financial workflows.
