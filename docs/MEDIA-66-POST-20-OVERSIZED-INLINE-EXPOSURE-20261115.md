## Acceptance and reversible staging plan

- Site QA runs **its existing** cold browser collector; only complete request chains, true transferred bytes and actual decoded images qualify as visitor claims. On the same 61-page sample, compare baseline vs staged candidate with same viewport, cache state and request inclusion rules; count **transferred image bytes**, not metadata `filesize`, encoded vs decoded conflation, or headline stored-original sums. Thus the prior **76%** target is explicitly **NOT_MEASURED**.
- Once a genuine missing slot is established, identify exact photo/crop/caption from its original URL and an authoritative Navy, Coast Guard, Florida Memory, USGS, NASA or other primary catalog record. Item-level rights/credit must authorize the proposed **specific** caching or republishing. USCG general public-domain statements do not clear every borrowed/donated image; archives' ownership and re-use permissions can differ.
- For authorized candidates, compute `w=min(960,nativeWidth)`, `h=round(nativeHeight*w/nativeWidth)` without upscaling. Verify landmark/diagram text at representative mobile/desktop sizes. Prefer immutable, rights-cleared WordPress attachment with preserved attribution, responsive `srcset`/`sizes`, explicit width/height and rollback snapshot; QA on isolated staging only. No WordPress production media upload, editing, global Jetpack bypass, unsafe Gutenberg block replacement or paid CDN purchase.
- Any proposed 76% reduction must satisfy the existing v4+ cold-image CDP paired-evidence gate (same requests, complete cold chains, response and cache accounting, transferred byte sums). The audit in this sprint has **no numeric HTTP status, no cold browser image result, and no wire-byte measurement**, correctly represented as null.
