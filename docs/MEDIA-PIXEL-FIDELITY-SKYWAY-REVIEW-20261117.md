## A concrete false-savings defect (now corrected in the draft)
The independent `qa/media-recovery/slot_parity_61_20261117.cjs` before/after assessor previously required an HTTP 200, positive image transfer bytes and `decoded=true`, but did not compare the **decoded native pixel dimensions between before and after**. A synthetic baseline of a 640×480 image, 4,000 recorded bytes, compared with a decoded 1×1 placeholder of 400 bytes was accepted as **90% reduction**. This is not a legitimate image preservation result.

The patched assessor now rejects paired image slots unless (a) all four natural-dimension integers are 1–100,000, (b) the final image long edge is at least `min(480px, baseline long edge)`, and (c) aspect ratio stays within 2% of baseline. These are conservative **HOLD** heuristics for visual-integrity and historical crop preservation, not a claim that 480px is an ideal sitewide display size or that matching dimensions prove matching photographic content. Individual rights, frame/crop, visual identity and screenshot review remain mandatory. This does not change site images or alter the existing Site QA collector.

New checks cover proportional 4K→960×720, the 4,918×6,136→769×960 portrait, an unchanged 600×463 historical preview, and a 4,000×400→960×96 panorama, plus 1×1 and 64×48 placeholders, aspect distortion, and invalid dimensions. An independent standalone native Node geometry script passed **10/10 checks**. The patched actual module was loaded in isolated V8 with compatibility shims: **8 focused geometry cases and 2 end-to-end assessor cases passed**; the earlier module accepted the 1×1 synthetic 90% result, the patched module threw HOLD, and a normal 61-post-schema subset was still accepted. Ten new regression tests were appended to the existing 50-case Node-targeted suite. **That full 60-case native module suite and repository CI have NOT run.**
