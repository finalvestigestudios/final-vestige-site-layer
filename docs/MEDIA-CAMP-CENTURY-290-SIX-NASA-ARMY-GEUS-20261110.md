## Safe performance methodology and production-hold plan

The reported **42 broken original external-source images** are only a historical allegation until **logged-out browser** tests and origin/network status identify exact breakage. The proposed **76% reduction** has **not been measured**. Run three reproducible **cold-cache** sessions per target page at mobile 390×844 and desktop 1365×768, collect every actual image request (including `srcset/currentSrc`, redirects, transfer response `encodedDataLength` with cache flags), and compare the **same image identity, crop, context, DPR, page and device** before/after in staging. Formula: `100 × (baseline actual uncached encoded image bytes - staged actual uncached encoded image bytes) / baseline actual uncached encoded image bytes`. Unknown, opaque or cache-hit bytes remain unknown; do not silently record zero or infer savings from stored attachment sizes. Check LCP/CLS, full-scroll and mobile captions/diagrams.

Historical oversized WordPress baseline: **15 original attachments above 1,500,000 bytes, totaling 47,096,779 stored bytes**, not guest transfer. Five published PNG originals in posts 34–38 reportedly have no generated subsizes. Some larger attachments have responsive sizes; measure what browsers actually fetch.
