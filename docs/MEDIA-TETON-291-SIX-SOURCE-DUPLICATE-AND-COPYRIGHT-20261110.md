## Real image failures, sizing and 76% weight claim — how to verify before action

1. **Load proof belongs to Site QA:** Use its existing logged-out Chromium mobile/desktop full-scroll collector, not text retriever. For each original image record the page and slot, DOM `src`, `currentSrc` after lazy loading, all responsive selections, effective request URL and redirects, actual response status, `complete`, `naturalWidth/naturalHeight`, console errors, CORS/CSP/referrer behavior, and cache hit/miss. A 403 to a HEAD probe or a web parser failure does not establish a broken browser image. Original six P0 checks remain higher priority.
2. **Size ceiling:** After license/identity proof, deliver optimized photographic variants at **min(960, verified native width)**; proportional height **round(width × native_height / native_width)**. Never upscale low-resolution historical originals. Preserve full-resolution zoom for text-heavy diagrams and needed research images. Do **not** treat URL parameters (`1200x800`, `quality/90`) or image preview canvas size as native file measurements.
3. **Performance methodology:** Capture uncached **same page, viewport, DPR, image visibility and identical source content** before and after. Sum **actual transferred image response bytes** for visible/loaded images, distinguish cached/not-transferred from transfer, repeated URL from repeated image slots, responsive `srcset` sizes from stored WordPress attachments; report `reduction = 100 × (before_bytes - after_bytes)/before_bytes`. The reported **76%** is still **unmeasured**, not an achieved result.
4. **Oversize methodology:** Historical worklist baseline has **15 original WordPress attachments >1,500,000 decimal bytes**, aggregate **47,096,779 stored bytes**, eleven referenced inline across eight posts. This is *stored original weight*, not transferred visitor bytes. Compare actual served image variants and cold request bytes before promising improvement. `docs/IMAGE-WEIGHT-WORKLIST.md` was not found on default branch or media recovery branch during this sprint; existing register baseline retained without extrapolation.
5. **Reversible media pathway (NOT executed):** Only if a source fails in real browser **and** rights/attribution, exact photographic scene, pixel identity and item metadata are cleared: create a licensed, checksum-documented 960px-max derivative in an isolated staging plan; review crops/legibility and page integrity; attach author/credit/rights/title/ALT, canonical archive source; prepare a reviewed WordPress Media Library upload then a precise block-level substitution under a separately authorized change, keeping the original and rollback identifier. No blanket mirroring, no unlicensed scraping and no risky full-post Gutenberg rewrites.
