Two PDFs can have the same filename. Two scans can depict the same document while holding different bytes. A folder called “original” is not a chain of custody. The first useful question is smaller: is this file exactly the same sequence of bytes as the one I recorded before?

A cryptographic checksum helps answer that question. It can establish a repeatable comparison of digital file contents. It cannot establish who wrote the record, whether the original was forged, whether the catalog description is correct, or whether the scan is complete. The distinction matters most when a digital copy looks authoritative.

What a file fingerprint actually proves

SHA-256, specified by the National Institute of Standards and Technology, produces a 256-bit digest commonly written as 64 hexadecimal characters. A changed byte will ordinarily produce a different value. Two independently calculated SHA-256 digests that match strongly support byte-for-byte identity, provided both calculations and the baseline are trustworthy. A matching digest does not make an unreliable source reliable.

The Library of Congress's digital collection integrity guidance describes retaining fixity metadata and audit logs. The U.S. National Archives audio preservation specification describes rechecking a checksum after transferring a newly captured file to long-term storage. These are integrity controls, not tests of historical truth.

Three separate witnesses: identity, fixity, meaning

Identity. Capture the archive name, collection and item identifier, exact download URL, original filename, byte count and date. Distinguish a stable archival record locator from a temporary image-viewer link. Record the object you selected, not merely the search result that led you to it.

Fixity. Calculate SHA-256 on the complete file. Preserve the result with the identifying metadata. When you later copy the file to another drive or download it again, calculate a new digest and compare. If the values differ, do not instantly call it tampering or damage. A PDF repackaged with searchable text, a rescanned image, a changed metadata field, and a genuinely corrupted file can all produce new hashes for different reasons.

Meaning. An unchanged copy of a mistaken transcription is still a mistaken transcription. A stable bitstream tells us the copy is unchanged, not that a date, name or attribution is correct. Use The Archive Trail to examine the primary record, and The Page That Changed when a public record has been revised at a persistent address.

When two checksums disagree

First confirm that both digests were generated with the same algorithm against the full intended files. Then check whether either file was intentionally transformed: OCR added to a scan, metadata rewritten, images recompressed, a PDF optimized or a restoration made. Save both original and derivative, label their roles and note who made the change. If no earlier trustworthy digest exists, make an explicit baseline today; you cannot prove retrospectively that an unrecorded older copy was unchanged.

A ten-field field card

  1. Exact original filename and extension.
  2. Institution, collection, series and stable item locator.
  3. Original source URL and access route.
  4. Date obtained and person or process acquiring it.
  5. Exact file size in bytes.
  6. SHA-256 digest and software/tool used.
  7. Date and provenance of any reference checksum.
  8. Comparison result: match, mismatch or no baseline.
  9. Known transformations, omissions and limits of interpretation.
  10. Access and reproduction rights, backup copy location and next integrity review.

Keep the receipt separately from the file being checked. Never overwrite the only earlier digest when deliberately creating an access derivative. A checksum without a trustworthy provenance ledger is a highly precise answer to a question that has been lost.

The free offline workbench

The accompanying standalone HTML review edition provides local-only SHA-256 checking, an optional trusted-baseline comparison, printable evidence fields and text-receipt export. It does not upload files or retain user input. The workbench sets a 100 MiB file limit to avoid excessive browser memory use. The standalone tool is held for site hosting and production-browser review: an unpublished draft must not suggest that its download is already available to public readers.

What this method does not replace

An integrity receipt is not a backup, virus scan, digital signature, legal evidence-custody certification, authentication test or rights clearance. File copies should be stored separately and checked periodically; a digest cannot restore the bytes of the only lost copy. The Digital Preservation Coalition's handbook explains checksum comparison, manifests and multiple copies. The National Digital Stewardship Alliance's Levels of Digital Preservation, updated to version 2.1 in March 2026, provides a broader preservation-planning framework.
