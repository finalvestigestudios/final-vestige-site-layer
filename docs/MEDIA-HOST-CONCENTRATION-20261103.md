# Final Vestige — 61-post external-media host concentration (2026-11-03)

## Scope and finding
This is an **offline risk-topology audit**, not proof of outages or actual downloaded image weights. Using eight frozen October 30 source parts (**61 posts, 355 inline image references**), the deterministic host analyzer finds **80 recorded source hosts**, **288 externally originated references** (170 external + 118 Wikimedia Special:Redirect/file), **60 direct first-party** and **7 first-party via Jetpack**. There are **36 posts whose stored images are all external**, including **17 posts whose every stored image points to one external source host**.

Concentration is material for remediation **prioritization**, not evidence that those images fail: Commons redirect URLs **118 images / 20 posts**, `upload.wikimedia.org` **18 / 10**, `www.history.navy.mil` **15 / 4**, USGS `d9-wret.s3.us-west-2.amazonaws.com` **9 / 2**, Florida Memory **7 / 1**, NPS **6 / 1**. On the stored-src layer, **post 407 (Hebgen Lake) has 8/8 USGS S3 images**, **post 432 (Okeechobee) 7/7 Florida Memory**, **post 280 (USS Pueblo) 6/6 NHHC**, and **post 211 (Port Chicago) 6/6 NPS**. These four represent article-level dependence on a single recorded upstream. Direct Commons `Special:Redirect/file` URLs may ultimately redirect to different Wikimedia serving endpoints; this audit does **not** treat them as identical final network destinations.

The recorded transport proxy host `i0.wp.com` has **9 entries across 3 posts**, not nine first-party originals: **seven** are inventoried as first-party Jetpack and **two** as external. A source-host count must not be mistaken for a `currentSrc`/final-host CDP count. Site QA #154's earlier 286 offsite number counted only direct offsite sources, while our 288 includes two externally originated proxy URLs. No discrepancy in the underlying total.
