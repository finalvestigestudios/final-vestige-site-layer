## Visitor-visible failure evidence: important detection gap closed
The prior `browser_probe_core.cjs` only classified a completed, zero-decoded-width image as confirmed broken when the matching browser image network request failed or returned HTTP 4xx/5xx. This missed an ordinary failure mode: a hotlinked remote image may return **HTTP 200 with an HTML/XML/JSON access-denied, login or error page**. The browser displays a broken image despite the nominally successful response code.

The probe now also requires **all** of: independently verified FV page; DOM image slot matched conservatively to its stored source; `currentSrc` identity verified; `complete === true`; `naturalWidth === 0`; an **actual matching browser image-network response** with HTTP 2xx and a distinctly non-image MIME of `text/html`, `application/json`, `application/xml`, or `text/xml`. Only then it records `confirmed_broken_in_probe_browser`, `visual_failure_kind: "non_image_error_payload"`, original HTTP status, and decoded response MIME. HTTP >=400 is separately `http_error`; a network error is `network_error`. An unreadable JPEG with MIME `image/jpeg`, missing request proof, absent MIME, unfinished lazy load, wrong `currentSrc`, or blocked page **does not** receive this new broken classification. This is code correctness, **not a newly observed live failure**.

Committed `qa/media-recovery/test_browser_probe_2xx_error_payload.cjs` contains 12 deterministic scenarios. Exact-GitHub-source isolated V8 replay **12/12 PASS**; not native Node CI. Browser `network_images` already collects real CDP response MIME without making additional requests, and recorded slot now includes `response_mime_type` and `visual_failure_kind`. No website CSS/content changed.

## What can happen next safely
Use the already-committed Chrome CDP probe to collect *real logged-out* mobile and desktop requests and screenshots. Triage genuinely missing images first, including any HTTP-200 non-image error payloads. For a **proven failure**, follow archival identity to the exact item; obtain rights and credits; hash original; produce ≤960px no-upscale derivative; stage WordPress responsive media and check visual integrity; then seek explicit production release permission. Do not proxy access-controlled images, scrape or hotlink unlicensed assets, alter Gutenberg raw blocks, claim a 76% weight reduction from Media Library original bytes, or treat a web image viewer's render as a Chrome GET/status.
