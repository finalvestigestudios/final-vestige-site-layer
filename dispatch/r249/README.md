## Genuine received email — safety
Current WordPress docs at https://wordpress.com/support/newsletter/email-appearance/ specify that the native preview control appears with the per-post email toggle ON. Other prior notes said OFF was permitted: **the live UI remains untested**. No toggle, draft creation, test email, or publication is authorized. Do not confuse WordPress's visual email preview with *received* email.

`receipt_gate.cjs` takes an **already redacted** actual received message's header values and recipient-visible extraction only once an authorized test exists. Reviewer supplies opaque private `evidence/` references, never public identities. It distinguishes subject, screenshot-observed preheader, genuine publisher postal address (Automattic address doesn't qualify for FV), visible unsubscribe and separate opt-out-function evidence. A static parser can never prove actual unsubscribe operation, double-opt-in/welcome delivery, affiliate channel permission or real revenue. It always returns `authorized_to_send=false`, `released=false`, and revenue NULL. All synthetic tests are incapable of release.

Do not place real subscriber addresses, raw .eml, business private address, opt-out tokens or affiliate account secrets in this repository. Handle testing only in a separately approved private QA space and publish sanitized aggregates. FTC physical-mailing-address and operational opt-out duties: https://www.ftc.gov/business-guidance/resources/can-spam-act-compliance-guide-business.
