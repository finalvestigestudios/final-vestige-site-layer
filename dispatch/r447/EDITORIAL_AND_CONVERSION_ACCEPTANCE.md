## Compliance and release logic

FTC's [CAN-SPAM guidance](https://www.ftc.gov/business-guidance/resources/can-spam-act-compliance-guide-business) specifies non-deceptive headings, commercial identification where required, valid publisher physical postal address and an easy functioning unsubscribe. The merchant's UK address and Automattic's postal address **are not** automatically the correct Final Vestige sender address. A generic privacy link is not proof of an email-specific opt-out. The independent [FTC endorsement guidance](https://www.ftc.gov/business-guidance/resources/ftcs-endorsement-guides-what-people-are-asking) requires material affiliate relationships to be clearly disclosed near the recommendation.

WordPress's [Email Appearance / Preview](https://wordpress.com/support/newsletter/email-appearance/) supports a **non-sending** native preview separately from its **sending** test-email action. This run's connected read actions cannot witness that visual rendering. The non-sending workflow still needs a human/authorized UI witness, plus final explicit send authorization afterward.

Source-only [contract.py](contract.py), [test_contract.py](test_contract.py), and [RELEASE_WITNESS.json](RELEASE_WITNESS.json) separate observable inventory, new consent, per-issue legal/merchant proof and settled revenue. They do **not** install event hooks, open PRs for Claude's backend, access subscriber addresses or authorize sending.

**Decision:** Keep campaign draft review active but no mailing until specific gates can be evidenced. The exact commercial KPI, realized net revenue per 1,000 qualified human sessions, is **NOT COMPUTABLE**, not an observed zero.
