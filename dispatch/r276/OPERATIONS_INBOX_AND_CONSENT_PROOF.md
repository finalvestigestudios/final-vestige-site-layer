## No-contact acceptance recipe, to run ONLY after founder separately authorizes a controlled test
1. Record founder approval covering exact recipient/control inbox, whether an email actually can be sent, send method, test campaign and rollback. Keep post auto-send OFF. Never contact existing subscriber list as a test.
2. Obtain independently verified eligible subscriber aggregate from provider; record counts and semantics privately without raw email addresses. `confirmed_signup` only upon first provider-authenticated subscription with consent provenance (some already verified WP.com users need no additional click). Deduplicate by stable provider ref; opted-out/reconfirmed changes go into lifecycle transitions, not new leads.
3. If approved, receive a real first-party Jetpack message at a dedicated opt-in test mailbox. Capture timestamp, full RFC 5322 MIME locally with access restricted, exactly where subject/preheader render, message body/full versus excerpt, from/domain, unsubscribe URL behavior, valid publisher postal address, visible near-offer disclosure, dark-mode/mobility/accessibility. Verify CTA opens signed-out. This procedure is NOT authorization to send.
4. Inspect the welcome message as delivered, verify linked PDF actual HTTP response `200`, correct content type, parse binary page count, observe browser-opening on mobile. Separate registration, delivery, and download success states. A sender name or redirect alone proves none of these.
5. Confirm unsubscribe in controlled authorized context; ensure no future marketing to suppressed address and no conflation with seller newsletter opt-in. Never log or publish full recipient identities, one-time tokens or private MIME.
6. For actual affiliate CTA, authenticate account-specific Inspire3 approval and written **email channel** permission, approved creative and earning-link syntax, current exact destination/refund terms and Mind-owned published guide. Review FTC proximity disclosure and CAN-SPAM advertising identity separately.
7. Merchant-settled purchase evidence must be independently authenticated and refunds/fees reconciled; maintain 7/30-day cohorts, tiny sample cautions and `null` KPI until verified. Never convert clickstream into claimed sales.

## Important practical reality
The offline HTML previews of original issues already exist under PR #1978. Their accessibility/markup checks and GitHub identity **do not** make them native Jetpack output; rebuilding more previews would not resolve the inbox blocker. PR #201 similarly already supplies per-issue release gates. R276 provides newly timestamped official route drift, a *separate* current-evidence custody ledger, and a stricter fail-closed contradiction check, not replacement previews or a new analytics script.

The FTC CAN-SPAM guide requires honest headers/subjects, advertising identity where relevant, valid physical postal address, and a workable opt-out. A publisher's genuine mailing address must be provided by the business, not inferred from a vendor, Automattic, or a website footer.
