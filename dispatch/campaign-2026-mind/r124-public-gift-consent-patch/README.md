## The actual implementation proposal
`focus_patch.cjs` exports a pure `proposePatch(fullAuthenticatedWordPressPageContent)` operation. It rejects fragments, duplicate/missing source signatures, unexpected script drift, and reapplication. It never calls WP, network, a browser, email, analytics or commerce. The source-matched output:
1. Removes the incorrect client-side `fvf-gift-v2` "confirmation" reveal behavior completely; changes the already-public `fvf-gift` panel from `hidden role=status` to a visible `role=region` with a named accessible label. There is **no subscriber-authenticated gate** to a public PDF.
2. Preserves exactly one original Fieldbook PDF URL, the original `focus_pdf_click` event, and its download CTA, but changes `data-fv-location=after_signup` to `public_pdf` so it is not falsely positioned as proof of signup.
3. Rewrites the false confirmation and mobile "sign up again" advice. Downloading does not opt a reader into Dispatch; native WordPress confirmation, suppression, send eligibility and received welcome remain separate.
4. Labels the existing five in-page signup CTAs **"Join The Dispatch (free)"** rather than promising that their click automatically sends the already-public file. Leaves all `focus_signup_click` event names intact and keeps the Jetpack block and consent language in place. The Jetpack-owned *form button* still displays "Send me the fieldbook" in the current serialized markup; Claude must separately assess its native rendering and make any necessary editor-level clarification only after release approval.
5. Preserves all existing analytics except the clarified `public_pdf` location; no new script or tracking. **No new `confirmed_signup` event is emitted.** That event requires authenticated native consent + opaque dedup as defined in #1000.

**Business tradeoff:** public download might reduce the fraction entering the email form, but fixes misleading confirmation signals, improves returning-subscriber experience and reduces redundant signups. This is a hypothesis, not a measured uplift. The lead's purpose is to nurture a *willing* reader; a UI-gift reveal is not a lead, and neither is a purchase.
