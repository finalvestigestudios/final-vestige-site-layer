## Offline use / privacy boundary
1. Only with explicit founder authorization, a site operator exports or locally supplies an already received, legitimate .eml **without involving the current subscriber list**; keep it **outside GitHub, Drive and issue comments**.
2. On a private local machine run `python audit_received_email.py /private/mail-evidence.eml --expect welcome` (or `editorial`, `commercial`, `confirmation`). Uses only Python standard library; **no HTTP, SMTP, WordPress or Gmail operations**.
3. Output JSON booleans/review flags only. No email addresses, subject text, header content, URLs, unique tokens, tracking IDs, message body, or buyer records are printed. Do not share the .eml.
4. **Mandatory manual checks still open:** actually received provenance with verified timing and recipient opt-in; precise visible CTA and preheader rendering on real email clients; prominent near-CTA disclosure; Final Vestige **own** valid publisher physical address; authenticated functioning unsubscribe/suppression with authorized isolated recipient; seller-specific email permissions; postal and content legal review. `List-Unsubscribe` or an anchor is a **signal, not proof** of a working opt-out. Filename in welcome is a **signal, not proof** the 52-page PDF opened.
5. Outputs **always** `HOLD_UNSENT`. Synthetic tests are not Jetpack preview/delivery validation. Never set a production email toggle or send, even a test message, in this lane without founder's explicit final campaign approval.
