## Specific substantive finding — R250's plausible visual false positive
The exact R250 `browser_evidence_gate.cjs` at blob `1738d14e48a5ed091f18ffd925e00c2c2501d6ac` accepts aggregate positive counts of a visible labeled email input, a button, and reachable subscription area. It does **not** establish that the button actually belongs to the email field's form. A deliberately malformed *offline fixture* with a labeled email input in a form **without** a submit, plus a separate unrelated button in the same Subscribe block, produced `VISUAL_ENTRY_PRESENT_UNSUBMITTED / visual_entry_pass=true` in an isolated V8 execution of the exact R250 gate (with URL shim). This is a false positive for **form-action binding**, not evidence of a broken live signup. R250 itself still properly refuses confirmed-subscription and release assertions.

## New R251 additive correction
`form_proof.py` inspects the DOM **without typing, clicking, navigating or making network requests**. It only provides positive *visual form association* evidence if a visible, enabled and labeled email input is paired with an enabled and visible **submit** control inside its same form and same subscription-block/dialog context, with same-origin form target. An accessible input with a neighboring unrelated button, absent form, placeholder-only label, disabled submit, hidden honeypot, or external form target is **not positive proof**. Valid popup form can be recognized. Legitimate JS-only actions without a native form remain **UNPROVEN**, not *broken*. This conservative gate supplements R250 and cannot certify receipt, opt-in, welcome, legal footer, conversion or revenue. It never creates a subscriber or sends email.
