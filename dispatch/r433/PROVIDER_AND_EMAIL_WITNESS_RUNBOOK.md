# One no-send acceptance runbook — evidence scopes must not leak private addresses

## Recipient reality, without exports
1. Sign in to **Jetpack → Newsletter → Subscribers** at the existing connected site. Read-only choose **Add filter → Email subscription → Subscribed** and separately **Not confirmed**, **Not sending (any reason)**, **Bounced** and **Emails paused**. Capture only status label, aggregate count, observation time, and platform account/site identifier in a private evidence note. Do NOT export CSV, copy email addresses or contact anyone. Record "eligible_inboxes" only if WordPress's filter and additional category/notification conditions support it.
2. Keep dashboard `total=3`, `confirmed=3`, `unconfirmed=2` and Reader3/email0 as **different scopes**. The WordPress support documentation says Not confirmed is excluded from the total. Avoid the false deduction that there are five receivers OR zero receivers.
3. Locate the existing authorized account's October **Confirm your subscription** received message and follow only read-only operations. This message is a challenge to confirm, not proof that the address clicked or that the 52-page welcome/PDF was delivered. Search for the welcome subject/body in that inbox; if absent, record "not found in checked inbox" rather than "everyone never got it". Do not click confirmation (it changes subscription), resend confirmation, or test subscribe.

## Actual native email rendering (approval required for any CMS write or outbound email)
4. After founder permission for a safe **WordPress editor draft** and chosen *clean* final content, use the native Newsletter **Preview email** action (non-sending) to observe actual subject, initial text/preheader and body on desktop/tablet/mobile. Capture date, screenshots redacted to remove account/session data, permalink of draft in internal evidence, **never** claim a browser HTML preview is a native email.
5. Separately, only with explicit founder authorization to send to a consented test inbox, inspect a **received** genuine email message (MIME + screenshot) to verify real From/Reply-To, text fallback, publisher **valid physical postal address** and a functioning unsubscribe workflow. A simple anchor in a source file does not prove Jetpack inserted a lawful opt-out. The account's email default still remains OFF after testing unless founder approves a change.
6. Business postal address must be provided and independently attested by founder as a valid street address, qualifying PO Box or registered private mailbox; do not fill with a guess or automatically borrow Automattic's confirmation footer. Preserve private residence privacy where possible by using a lawful business mailing location. No change is requested here.
7. Do not create a newsletter category, add an email platform, switch Reply-To, send test messages, or import recipients as part of this protocol. Changing `reply_to=no-reply` is a separate founder decision; it means subscribers cannot simply reply for feedback, and the site must not promise a two-way reply channel.

## Safe event contract for Claude/Focus, not an installation
`confirmed_signup`: ONE logical event per provider-verified subscribed transition and stable opaque provider subscription key; never on button click or form submitted. Two equivalent records for the same key count once, including WordPress.com accounts that may not require clicking a new confirmation email. Persist no plaintext email, telephone, IP or raw tracking token in Dispatch's aggregated release report.
`utm_source=dispatch; utm_medium=email; utm_campaign=dispatch_pilot_2026_11; utm_content=issue_01..issue_06`: proposed, not deployed, only to verified first-party destinations, not merchant links. Grok keeps `utm_source` as actual platform and `utm_content` as source immutable asset_id. Do not overwrite upstream asset lineage in the user journey when email becomes a later touch.
`paid_sale`: only partner/payment-provider independently confirmed completed/settled order, deduped by opaque transaction key; apply documented refunds, fees and attribution eligibility, 7/30-day cohort and cohort maturity. A click, warm-up view or checkout-start is never a sale. If revenue or qualified human denominator is unknown, KPI is NOT_COMPUTABLE.
