## Actual code read and defect addressed

The Research Desk candidate in PR #158 includes `experience2/research-desk/assets/source-ledger.js` (blob `57f4a639d4c37fc4355b10fe7dec085bf87c6eb7` on the R151 base), its PHP adapter and the six-record `templates/ledger.html`. The source-search script restores a hidden chronology destination **only if the user clicks a `data-fvx-chrono-link` inside its own Research Desk**. It does not handle navigation by an external anchor, browser Back/Forward hash history, or the address bar while a record is hidden by search. A visitor can thus arrive at a hidden evidence record. This is a component-level keyboard/navigation continuity risk, not a verified defect on a deployed Research Desk.

R152 stages a **replacement candidate**, not an automatically wired patch: `r152_source_ledger_hash_bridge.js`. It listens for hash changes; recognizes only record IDs within its own desk; reveals the target if search hid it; focuses that article with temporary `tabindex="-1"`, without creating a permanent tab stop; preserves native anchor navigation and visible source links; restores all records if the source search index is malformed; avoids network, storage, injection and third-party scripts. It also cleans up the hash listener when filter initialization fails. The hash is decoded defensively.

Do **not** load this script alongside PR #158's existing script: both initialize `data-fvx-ledger`, so staging integration must use one implementation at a time after review. This sprint deliberately leaves the working PHP adapter and asset paths untouched.
