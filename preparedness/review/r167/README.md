# R167 — Family Card active browser privacy-sink regression gate (DRAFT / HARD HOLD)

**Authority:** Preparedness issue #136; conversion coordination #820; charter #818. **Parent:** R166 draft PR #1246 at `bafbbf2ae0c4e06e3d44e32257abb8f5e41ddebe`.

**Reason for this increment.** R166's Chromium fixture tests page routing, storage remaining after reset, minimal-card rendering and print layout. A transient write that is cleared before the final storage check can evade that class of check; WebSocket and other non-fetch APIs are also not equivalent to intercepted HTTP requests. R167 installs a pre-document, browser-local, no-payload sink detector before rendering, and checks at page initialization, typing, minimal-mode selection, and form reset. It observes and blocks attempts through fetch, WebSocket, EventSource, XMLHttpRequest, Worker, SharedWorker, BroadcastChannel, WebRTC, Beacon, local/session storage, IndexedDB, submit/requestSubmit, ServiceWorker registration, clipboard, object URLs and document.cookie. Network URL collection is restricted to the *scheme*, with any nonlocal request blocked. The regression probe cannot prove privacy across browser extensions, the WordPress runtime or the browser's non-JS internals. The patch is not a hostile-JavaScript security boundary.

**Authentic execution requires a complete trusted checkout.** The CLI first executes R166 (which executes R165 + immutable 35-article source custody), confirms its staged Family Card dependency hash, and then runs the stronger R167 probe. The report always says `DRAFT_HARD_HOLD` on success or `INVALID_HARD_HOLD` on error; CLI **always exits 2**. No structural success may set QD PASS, source adjudication complete, medically safe, or release authority.
