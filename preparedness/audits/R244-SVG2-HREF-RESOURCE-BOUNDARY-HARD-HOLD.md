## Verified independent QA discovery, negative control, correction

Praxxis' latest dated handoff independently identified a gap in R243: the browser's SVG 2 `<image href="...">` can fetch a remote resource. R243 checked `xlink:href` as a resource, but its ordinary `href` path counted even non-anchor SVG attributes as navigational links. A non-rendered third-party image/tracker could therefore appear in authored source HTML even though scripts and image `src` were blocked.

**Reproduced against exact old Git blob** `17f8afe62caadd32d149d8e7dd6bdf8fd066302e`: `<svg><image href="https://tracker.example/one-pixel.png"/></svg>` returned `DRAFT_HARD_HOLD` with no error. This is a **validator bypass**, not evidence that the current original manuscripts contain such an image or that a browser actually issued a network request. In the corrected exact Git blob `fd44288b0009811f1812ede1d618f2290308ed7e`, the same source raises `R244 nonnavigation href loads unreviewed resource: image`.

**Fix:** Read all `href` and `xlink:href` attributes according to element function. Only actual `a` / `area` navigation can retain ordinary reviewable external links; every other element requires a tightly parsed same-document `#symbol-id` reference (whether raw or HTML-entity encoded). All nonfragment destinations on SVG image/feImage/use/mpath/textPath/tref/pattern etc., including remote HTTPS, relative paths, and encoded URLs, fail closed pending a vetted asset manifest. Existing safe static SVG geometry and fragment-based <use> / <textPath> work. Trusted `{{link:...}}` and `{{cite:...}}` source tokens remain unchanged. Original source evidence and editorial safety states are never auto-approved.

**R220 custody integration:** existing before-producer authentication and after-audit Git-blob recheck of `tools/r243_active_source_markup_custody_hold.py` now pin exact `fd44288b0009811f1812ede1d618f2290308ed7e`.
